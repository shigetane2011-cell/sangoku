# 宝物（旧・恩賞）リスト叩き台［**実装済み（§7.138）・功は実測済み（§7.139）**］

> 2026-09-01 実装済み。実装の記録・造りの要点は spec §7.138、**功の実測
> 値付けは §7.139** が正で、この文書は相談の経緯を残す叩き台（本文中の
> 功はすべて古い仮値）。品揃えの正データは `sim/data/treasures.csv`。

2026-09-01 テストプレイの相談から。恩賞（§7.43〜§7.70）を「宝物」へ作り替える
ための第一稿。**このリストは相談用の叩き台であり、効果の数値は全部仮**。
採用が決まった宝物から §7.5/§7.53 の効果予算工程（帯合わせ・実測）で
値付けする。

## 決まっている仕様（テストプレイの回答 2026-09-01）

- 名称は**宝物**。三国志に出てくる書物・武具・馬・玉璽などの実在の（物語上の）宝
- 効果は**全て新規に作る** — 武将の生まれつき固有特性と同じキーを配る
  「かぶせ」は廃止（多少強くても全員条件は同じ、の方針）
- **同じ宝物は1人1個まで**（別種の宝物は複数所持できる＝収集の楽しみは残る）
- どの武将に持たせるかは選ぶ（装備先の概念は維持）
- 既存の恩賞データ（owned_traits）は**破棄してよい**（まだ誰も使っていない）
- 装備時の**功コスト制（§7.61 軍功予算）は維持する方向**（新効果の値段は要測定）
- 相手からの秘匿は §7.136 をそのまま継承（`hidden_trait` の器・実況の「秘策」）

## 未決（推奨つき）

- **1武将に宝物いくつまで持たせられるか**: 今の軍功枠3つは「渡せすぎ」の
  感触 → **推奨: 1武将1宝物**。「その将の愛用の品」という絵になり、
  枠パズルも消える。デッキ全体の積み過ぎは功予算（ONSHO_BUDGET_KOU）が
  引き続き頭を押さえる
- **入手の流れ**: 推奨は §7.70 の日替わり3択をそのまま流用し、候補を
  **未所持の宝物からだけ**引く（同一宝物1個の制約が抽選側で自然に効く）。
  全部集めた帯は「本日は在庫なし」— 収集が終わる日をどう扱うかは追って
- **図鑑**: 所持/未所持の一覧（収集要素）。実装は後回しでよい

功の目安は現行の帯（大50〜90・中15〜25・小0〜10）を仮置き。**実測で決める。**

> **設計注意（テストプレイの指摘 2026-09-01）: ゲージ経済 × 構え系兵法は
> 危険な相互作用クラス。** 構え系（田豊・王允の打消し、陸抗・郝昭・蒋琬の
> 兵法防御、朱桓の反射）はタイミングそのものが釣り合いで、§7.137 の実測は
> 田豊の公平性が「初動だけは通す」（自然の初動 約56秒 ＞ 早い/普通の1発目
> 約41秒）で保たれていることを示した。**初期ゲージ加算はこれを直接壊す**
> （+30 で初動37.5秒 → 早い/普通の1発目より先に窓が立ち、初動すら通さない
> 完全封殺が宝物1個で買える）ため、孟徳新書の初期案（初期ゲージ+30）は
> 効果ごと差し替えた。**初期ゲージを動かす宝物は今後も作らない。** 気勢
> （玉璽・玉帯詔）は初動を数秒縮める程度で初動保証は破らない見込みだが、
> 田豊の窓の連続性を強める側なので、採用時は「田豊に持たせた場合」を
> 個別に測る（計器は scratchpad/tianfeng_*.py を流用）。

### 勢力の宝 — 同じ部隊にその勢力の武将3人以上（仮）で効果が立つ（功は大帯目安）

テストプレイの提案（2026-09-01）。**利用条件つきの宝物**: 持ち主と同じ部隊に
その勢力の武将が3人以上（仮・持ち主も数える）いるときだけ効果が立つ。
条件は**戦闘時に数えるだけ**（陣頭の is_front 条件と同型）— セット時の
検証は要らず、条件を満たさない編成では黙って眠る。勢力寄せの編成を
組む理由になり、相手から見ても「蜀が3人…蜀の宝かも」という読みが生まれる
（§7.136 の「類推は許容」の範囲）。効果は4勢力で対になる全軍常在。

## 実装の当て（新しく要る器は5つ）

既存の器で賄えるもの: 誘発型（`TRAITS` の cond/target/cap の器そのまま・
新キーで登録）、寄せ（def_lean/spd_lean）、兵力調整、演出フラグ。
新設が要るもの:

1. **能力値への加算**（武力/知力） — `_apply_onsho` の書の分岐と
   同型で、`might/wits` への差分を写す枠（**初期ゲージへの加算は作らない** —
   大の設計注意のとおり、構え系の初動保証を壊すため）
2. **全軍常在**（勢力の宝4種） — 本陣の「持ち主が居ると全軍の兵力+3%」と
   同じ配線型を rate_mult/atk_mult/def_mult/兵力へ
3. **装備制限**（騎兵のみ・弓兵のみ） — セット時の検証1本
4. **勢力数の条件**（勢力の宝） — 戦闘時に同じ部隊の勢力を数えるだけ
   （陣頭の is_front 条件と同型・セット時検証は不要）
5. **打消し貫通**（七星宝刀） — `_apply_skill` の打消し分岐（§7.126）で
   撃ち手の貫通フラグを見る1行

秘匿は §7.136 の `hidden_trait` をそのまま継承。常在型はもともと実況に
出ない。誘発型は「秘策」の総称で発動だけ語られる — 1人1個の制約と
組み合わさると「どれを持っているか」は最後まで割れない。全軍の兵力を
動かす宝物（赤兎馬・蜀錦）は布陣行の総勢の数字にわずかに出る — §7.136 の
「履歴から類推程度は許容」の範囲と整理する。

## 測定の段取り（採用が決まったら）

1. 効果ごとに §7.53 の帯合わせ（そのコスト帯の効果予算 [最小,最大] に乗せる）
2. `design.trait_value` 相当の実測 → 功へ丸める（kou_of の流儀）
3. 全軍常在（玉璽）だけは単体計器で測れない可能性が高い — §7.52 本陣と
   同じ**勝率通貨**（§7.137 で田豊に使った手順・計器は scratchpad/tianfeng_*.py
   が流用できる）で測る
4. 気勢系（玉璽・玉帯詔）は上の測定に加えて**構え系兵法との相互作用を個別に**
   測る — 「田豊に持たせた場合」の初動時刻・窓の連続性（大の設計注意）
