## 1. いま何をしているか

### ★ 恩賞→「宝物」への作り替え（§7.138・2026-09-01・実装済み・功は§7.139で実測済み）

- 決定（叩き台 `docs/design/treasures-draft.md` を承認の上で実装）:
  三国志の実在の宝18種（大7・中6・小5）・効果は全部新規（生来キーの
  かぶせ廃止）・同じ宝物は1人1個・1武将に1個・装備先は選ぶ・
  日替わり3択（未所持からだけ）と軍功予算（功=cap×5）は維持・
  旧 owned_traits のデータは破棄
- テストプレイの発案で追加: 打消し貫通（七星宝刀）・勢力条件の宝4種
  （同じ部隊に魏/蜀/呉/群雄3人以上）。テストプレイの看破で**初期ゲージを
  動かす宝物は禁じ手に**（§7.137 の田豊の初動保証を壊す）
- 新設の器: perm恒久倍率（_recalc_mods の代入上書きに消されない）・
  全軍常在 _apply_faction_treasures・装備制限・打消し貫通（無言）・
  杜康の開幕台詞（mag=inf・prio=布陣の次）。誘発4種は traits.csv と
  同一文法で F.TRAITS へマージ、秘匿は §7.136 をそのまま継承
- リプレイの潜在バグを1つ塞いだ: 札を変える宝（武力/知力/寄せ）は純関数
  apply_treasure_card_mods に集約し **army_from_snap も呼ぶ**。旧・寄せの
  書は装備時だけ効いてリプレイ再構成で消えていた（snap は n/t/h しか
  持たない）。旧陣容の互換は不変
- 旧・恩賞系のコード（play.py の ONSHO_* 一式・players.py の軍功枠6関数
  ・TRAIT_SLOTS）は撤去済み。owned_traits の DDL だけ墓標で残る
- 受け入れ試験 tools/test_treasures.py（エンジン14＋HTTP5）・
  test_treasure_privacy.py（§7.136 の移植・snap 往復まで）
- 詳細は spec §7.138

### ★ 宝物18種の値付けを実測（§7.139・2026-09-01・CSVへ反映済み）

- §7.137 の勝率通貨計器を宝物用に組み直し（CRNペア測定・12性格×100種
  ×28条件＋補正4条件・SE±0.2〜0.7%）、**18種全部の功を実測値へ差し替え**。
  効果量は設計値のまま — 動かしたのは値段だけ
- 手書きの当ては最大10倍ずれていた: 青龍偃月刀 20→**110**（武力+15は
  白兵の物差しで+24%）・青嚢書 8→**65**（壁は4割線に長く居る）・
  赤兎馬 70→**9**・孟徳新書 60→**14**。当たっていたのは木牛流馬だけ（6→7）
- 全軍常在の効き順は **兵力＞攻撃＞気勢＞守り**（蜀錦100・倚天剣80・
  玉璽35・孫子19）— 兵力は耐久と打点の両方に載る（§6.1）
- 七星宝刀はプール2功・対田豊+427功相当（25.8%→46.5%）の保険 —
  一様な値段に均せないので**25据え置き**。打消し札が増えたら測り直し
- 玉帯詔は対田豊で倍化（+82功相当）— 気勢系×田豊は対策側に働くと確定
  （§7.138 の懸念は杞憂）
- 計器の教訓4つ追加（§7.139）: 生来値の上限張り付きで空回り（玄鉄×曹仁
  の±0.00は「小さい」でなく「空転」の印）・七星の持ち主は実際に打ち消され
  ている札に・勢力縛りの編成コストはこの計器では測れない・対田豊0%床では
  Δが出ない。計器は scratchpad/tp_lib.py・tp_report.py
- 帯と値段の食い違い（中帯110功・小帯65功）は仕様として容認 — 帯は
  日替わりの段、値段は実力。効果量の調整は別の相談
- 詳細は spec §7.139

### ★ 馬前（旧 庇護）と馬上回避（§7.144・2026-09-02・実装済み・テストプレイの提案）

- 提案「歩兵に周りをカバーする固有能力」→「庇うと馬上回避を少しだけ」。
  前衛の騎兵は弓型に対し被害の**7割が矢**で44秒で撤退（呂布・弓型120戦）
- **庇護**（常在 `cover`・`COVER_SHARE`=0.30・`COVER_ADJ`=600）: 前衛に置いた隊が
  両隣の前衛の矢の3割を自分の鎧で受け直す。後衛・近接・兵法直撃には働かない。
  典韋・許褚（のち陳到・周倉も）に2つ目の特性として。実況1行・詳録「庇護」。
  口は field.py の通常攻撃ブロック（A/B両側・`_cover_map`）
- **馬上回避** `CAV_COVER` 0→0.15（§7.73 の眠っていた蛇口）
- 受け入れ試験 `tools/test_cover.py`（6項目）。**相手側にも庇護持ちが入りうる**ので
  対照は両軍に掛ける。`dealt_a/b` の末尾に `covered` を足した — play.py の
  固定長アンパック2か所を直した（末尾に足しても壊れる読み手があった）
- 実測（隣に10コスト騎兵・赤壁40・同じ種でペア）: **庇護30%は +4.8〜9.0**
  （弓型への勝率 10〜25%→17〜38%・近接型は不動）＝ +1.0〜1.9 コスト点で、仮の
  値段 0.737 は安すぎる。**馬上回避15%は ±1 以内で何も動かさない**（相手の騎兵
  にも掛かる・乱戦12秒で消える）。割合は 20/30/40% でほぼ比例、30% を採用
- 決定（テストプレイ）: 庇護は**2つ目の固有特性**（典韋・許褚は陣頭＋庇護、陳到は
  殿＋庇護、周倉は背水＋庇護）。値段は土台10種の**単純平均 0.652**（最大値でなく
  アベレージ）。**隣が歩兵だと −3.3〜−4.4**（丈夫な隣の矢まで受けて庇い手が先に
  倒れる）— 騎兵の横に置く札。`CAV_COVER`=0.30 でも弓型へ +0〜2.5 と小さい。
  上限超えの2枚は兵法で収めた（悪来 1400%・捨て身の盾 800%）
- 馬上回避を**「接敵まで」**の形へ（テストプレイの決定・`Unit.eng`＝最寄りの敵の縁
  までの距離・`CAV_COVER_SOFT`=40m）→ 測ると **効果なし**（前線は数秒で触れるので
  窓が5〜10秒しかない）。次の候補「射手が遠いあいだ」（その射手との距離で決める）
  は実デッキで **弓型へ +3〜11・近接型へ −5〜10・全体 ±3**（兵種の規則なので相手の
  騎兵にも効く。騎兵対弓の偏りが縮む）→ **採用**（テストプレイ）。`_cav_cover` は
  射手との `box_gap` の窓。`Unit.eng` は外した
- 値付けの要約規則は**固定パネルの平均**に確定（3レギュレーション × 狙った置き／普通
  置き・6枠等重み。「最大値でなくアベレージ」「損になる置き方も制約のうち」）。誰でも
  庇う形は平均 +0.03 の両刃だったので、**B案「騎兵の隣だけ庇う」**へ（2e48e66）。
  B案の実測: 赤壁 狙った置き +1.07〜2.01・官渡 +0.09〜0.64・汜水関 +0.13・普通置きは
  構造上 0 → **値段 0.345**。兵法は 悪来 1500%・捨て身の盾 900% まで戻した
- 名前は**「馬前」に決定**（候補: 馬前・護駕・親衛・盾鞍）。変えるときは `field.COVER_NAME`
  と traits.csv の名前を揃える
- 残り: 弓の値付け（ACT_COEF）と、合成軍の三すくみ表が最後の較正から離れている件
  （歩→騎 −2.0・騎→弓 +8.8→+10.2・弓→歩 −0.8）

### ★ 呂布〔飛将〕はなぜ低いか（§7.143・2026-09-02・測定のみ・テストプレイの問い）

- §7.142 の「呂布 22.8%」は騎兵を後衛枠（置けない位置）で測った数字。合法な
  前衛置き・赤壁40・同じ土台で 関羽 40.4／孫策 49.2／孫堅 24.2／**呂布 39.4%**
  — 関羽と同水準。「前は高い」は v0.4 の陣頭持ち呂布と、騎兵を過大に出す
  `price_audit` の言い分（§7.77 で −4.9% 締めた根拠）
- 10コスト騎兵は4枚とも弓・軍師型に 10〜22%・近接型に 38〜76%（§7.108 の構図）。
  呂布は振れが最大（謀弩 2.5%〜疾風 90%）
- 効く蛇口は役割（瞬発→火力）だけ。防御寄せは結果に **±0.00**（兵力×防御を
  保つ設計＝演出量）、速度・対象・特性は ±2 以内。役割を火力にした札を CSV→sync で正しく作って
  同環境で測ると **+1.0 ±0.8**（in-memory の +6.9 は攻撃力の引き方が式と違う
  過大値。役割・寄せの差し替えは CSV→sync で測ること）
- 処置はテストプレイの判断待ち（紙装甲の一撃屋のままか、体を火力へ）

### ★ 3〜8コスト帯の差別化（§7.142・2026-09-01・実装済み・テストプレイの指摘）

- 指摘: 役割のかぶり（守りを上げるだけ・槍なのに前衛限定の能力）と関羽の
  個性不足。72枚を 兵種×役割×兵法型 で束ねて洗った: 「防御力+ → 味方1列」

- 関羽の実測（同土台で10コスト騎兵を差し替え）: 孫堅37.2・**関羽34.5**・
  孫策33.3・**呂布22.8%** — 関羽は弱くない。均衡役で攻撃力が帳面上半分に
  見える顔の問題。**呂布の低さは置けない位置の数字だった**（→ §7.143）

### ★ 軍功予算を cap×3 へ（§7.140・2026-09-01・実装済み）

- 値付けの実測で予算の購買力が3倍に膨らんでいた（同じ150功で2個→6個）。
  テストプレイの指摘「多すぎる気がする」→ 積み増し検算の上で締めた
- **検算: 宝物の価値は束ねても目減りしない**。官渡150功満載の集中型
  （青龍+玉帯詔）+7.50%・分散型（6個）+7.75% — どちらも値札合計の
  予測と1SE以内で一致。予算はそのまま「フル装備古参 vs 丸腰新規」の
  勝率差の天井になる
- 決定 cap×3（汜水関54・官渡90・赤壁120功）: 天井 +2.6/+4.4/+5.8%。
  下限制約は赤壁 ≥ 青龍110。最強の宝は赤壁でだけ担げる

### 陸抗「節制」— 一発目を保護し二発目以降を抑える（2026-08-29・試験導入）

持重だけではBO3の一面にしか効かず、敵だけを抑制すると双方が陸抗入り手数型へ
収束する懸念が出たため、陸抗〔羊陸之交〕の「殿」を**節制**へ差し替えた。

- 陸抗が自身の初回兵法を放つまでは何も起きない。
- その後も各武将は、自身の初回発動までは自然ゲージを通常どおり得る。
- 自身の初回発動後だけ、敵味方とも自然ゲージ増加を60%抑制（倍率0.40）。
- 初期ゲージ・与ダメージ給・被弾給は不変。非重複、陸抗撤退後も継続。

大技の一発目を奪わず、二発目以降への依存だけに代償を課す。相性が良いのは
大技型だけでなく、通常攻撃型と初回完結型。探索上位も手数1・標準4・大技1の
混成で、同じ6人を陸抗→張飛に替えた方が強く、節制による万能化は確認されなかった。

## 3. 計器の一覧と、それぞれが**測れないもの**

**これがこの企画でいちばん高くつく所である。** 計器は壊れていないのに、
適用範囲の外で読んで間違った結論に至る事故を何度も起こしている。

| 計器 | 用途 | 測れないもの |
| --- | --- | --- |
| `tools/one_ruler.py` | 札1枚の値付け（行ごとの物差し） | **「線を保つ」役目**。1対1の斬り合いしか見ないので**騎兵を過大評価する**。→ 下の落とし穴 |
| `tools/ladder_top.py combo` | 7つの型の総当たり（兵種の釣り合いはここ） | 個別の札 |
| `tools/senki_check.py` | 戦記52戦の坂 | 絶対値は目安（草案の強さは保証されていない）。**形**を見る計器 |
| `tools/skill_price.py` | 兵法・槍・特性の値段（実測 対 請求） | **討ち取りの割増の絶対値**（--sweep は環境で読みが4倍動く・§7.117）。換算は局所勾配へ直した（--zero が検査） |
| `tools/price_audit.py` | 全120枚の盤面残差（対称・零点が構造的に汚れない） | 騎兵は過大に出る（1枚担ぎの計器・§7.108）。味方依存の兵法（指揮系）は詰め物が味方なので測れない — 袁紹/費禕/劉表の -15〜-21 は札ではなく計器の外れ値 |
| `python3 -m sim.field traits` | 誘発型の特性の値段 | **釣り合った合成軍では誰も全滅しない** → `self_dead` は必ず 0.0000。`skill_price.py --trait` を使う |
| `python3 -m sim.rosterdata` | CSV・設計式・盤面の三者一致 | 盤面の釣り合い |
| `tools/type_edges.py` | 7型の総当たりから兵種の3辺（騎→弓・弓→歩・歩→騎）と型ごとの勝率。定数・表・ACT_COEF をつまみで振れる | 個札。1型の組が少ないと過適合（8組以上で） |
| `tools/card_before_after.py` | 札の書き換えの前後比較を**同じ環境**で（改修前の札を今の名簿・土台へ持ち込んで同じ種でペア） | 土台に依存しない絶対値。土台と相手の候補は固定なので「その土台での差」 |

### 落とし穴（全部いちど踏んだ）

1. **`one_ruler` の帯の中央を、兵種を混ぜたまま使わない。** 帯の中央は騎兵の
   枚数ぶん嵩上げされる。歩兵の札をそれと比べると、騎兵の過大評価がそのまま
   「この歩兵は安売り」という読みに化ける。**帯 × 兵種**で取ること（§7.114）
2. **兵種ぐるみの読みを値付けの根拠にしない。** 騎兵はここで最もお買い得と
   出るが、盤面では騎兵デッキが最下位（§7.108）
3. **`power_hi`（威力の幅）は種の無い測定では中央値になる。** `margin` 系の
   計器は振れ幅を一切見ない。振れ幅を測るなら `simulate(seed=...)`（§7.113）
4. **特性の値段を測るとき `trait=key` と書くと元の特性を消す。** 測っているのは
   「新しい特性 − 消した特性」になる。重ねること（§7.113）
5. **有り/無しで別のデッキを引かない。** 差が編成のばらつきに埋もれる
   （値 +0.42 に対し標準誤差 0.37 になった）
6. **上限のような量は整数で持つ。** `player_cap` が小数を返すと、草案が上限を
   丸めて組んでから丸めない値と突き合わせ、**組めた編成を自分で弾く**
   （52戦中22戦、のちに9戦。**2回踏んだ**）
7. **エンジンの定数を動かしたら、その挙動に値札が付いていないか数える。**
   `SPEAR_GUARD` を切り替えた回に `SPEAR_PRICE` を測り直さず、9枚が 0.75 を
   払って返り 0 のまま残った（§7.112）
8. **零点の怪しい計器で表を書き替えない**（§7.112 の `KILL_PREMIUM`）
9. **理屈で機構をいじる前に盤面へ聞く。** 「値打ち 0 ＝死んだ語＝機構を戻す
   べき」は筋が通って聞こえたが、外した瞬間に一強が生まれた（§7.112）
10. **指示された蛇口を先に開ける。** §7.123 でテストプレイが名指しした2つ
    （騎→弓・弓→歩）を既定0のまま置いて、指示されていない矢数の掃引へ
    進んでしまい、止められた。掃引で「効く蛇口」を探すのは指示が無いとき
    の仕事。指示があるならまず**その値**を入れて測る
11. **`multiprocessing.Pool` は `_roster_cards()` の後に作る。** 兵法と
    特性は `_roster_cards()` が field のグローバルへ積む。先に fork した
    子プロセスは**特性も兵法も空のまま**戦い、まるで別の勝率が出る
    （長駆の斧 0% が 44% に化けて、エンジンの再現性を疑う羽目になった）。
    F の定数を切り替える掃引も、fork 済みの子には**伝わらない** — Pool は
    状態を変えてから作り直すこと
12. **ACT_COEF の実行時差し替え掃引は部分適用**（兵力は CSV 由来で動かない。
    武・知経由の分だけ変わる）。`regenerate()` 込みの本適用は掃引時より強く
    出る（汜水関 95→78%・赤壁 82→88% と別物になった・§7.124）。係数を
    測るときは **regenerate してから測る**こと
13. **前後比較を別々のCSVで2回測らない。** 相手の候補は名簿から組むので、
    17枚書き換えた後の名簿で組んだ相手は前と別物（土台に触った札があれば
    土台も別物）。触っていない対照札が +3.5〜5.8 動き、それを「札が強く」と
    読んで4枚を弱くし、取り消した（§7.142 訂正）。改修前の札を**今の環境へ
    持ち込んで**同じ種でペアにする — 対照札も一緒に測る
14. **固定土台の6枚目を置けない位置で測らない。** 後衛枠に騎兵・槍なし歩兵を
    置いた数字は誰も使えない盤面の数字。土台を組んだら `match.placement_errors`
    を assert する（§7.142 訂正）
15. **一撃・手数の兵法は発動回数を数えてから値を読む。** 消費300の一撃は後衛
    からは 24戦中5戦しか撃てない（`simulate()` の `fires_a`）。撃てない兵法の
    威力を上げ下げしても何も動かない（§7.142 訂正）
16. **型の総当たりは「引いた札の組」の数で読む。** `_combo_army` の組は rng 固定で、
    1型2組（members 2）で較正すると**その2組に過適合**し、3〜4組で確かめると辺が
    15ポイント戻った。種（戦闘の乱数）より札の組の分散が大きい。評価は 8組×種1〜2
    （§7.145）
