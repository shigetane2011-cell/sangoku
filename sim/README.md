# 戦闘シミュレータ

仕様書 v0.5 の §5〜§8 を実装し、§4.6 のバランス指標が実際に測定できるかを確かめるための
検証環境。ゲーム本体ではなく、**数値設計の妥当性を測るための道具**である。

外部ライブラリは不要（Python 3.10 以上の標準ライブラリのみ）。

## ファイル

| パス | 内容 |
| --- | --- |
| `roster.py` | **武将ロスターの定義と `cards.json` の生成器**。人物・コスト・兵種・役割・必殺技だけを持ち、能力値はコストから導出する。 |
| `cards.json` | `roster.py` が生成する武将データ60人ぶん。**手で編集しない**。 |
| `engine.py` | 部隊戦の戦闘エンジン。§8.1 の12ステップをティックごとに処理する。 |
| `balance.py` | バランス検証ハーネス。§4.6 の指標を実測する。 |
| `budget.py` | 各カードがコスト式どおりの能力値かを検算する。ロスターを変更したら必ず通す。 |

## 実行

```
cd sim
python3 engine.py            # 1戦を実況付きで再生（動作確認）
python3 balance.py check     # 決定論・戦闘時間・決着理由・必殺技回数
python3 balance.py troops    # 兵種三すくみ（合計コストを揃えて比較）
python3 balance.py commander # 総大将の前衛配置と後衛配置の勝率差
python3 balance.py swap      # 差し替え勝率（§4.6 目標 47-53%）
python3 balance.py meta      # 採用率
python3 balance.py cost      # コストの加算性
python3 balance.py skills    # 必殺技のひな型ごとの強さ
python3 balance.py traits    # 誘発型の固有特性ごとの強さ
python3 balance.py formations # 陣形×構成の総当たり
python3 balance.py support   # 1枚だけ混ぜたときの寄与（必殺技の価格付けはこれで決める）
python3 balance.py exploit   # 攻略探索（最強編成を探し、収束するか循環するか）
python3 balance.py bo3       # BO3のマッチ勝率（1戦の勝率が3戦でどう化けるか）
python3 balance.py factions  # 勢力の規模と対抗能力の実効価値
python3 balance.py amplify   # 増幅の強さ（総合値の差が勝率へどれだけ拡大されるか）
python3 balance.py sensitivity # 総合値の差と勝率の差の換算率
python3 balance.py all       # すべて
python3 budget.py            # 能力値がコスト式どおりかの検算
python3 roster.py --write    # ロスターから cards.json を再生成
```

`swap` と `meta` は数万回の対戦を行うため、数分かかる。

## 武将を追加・変更したときの手順

**`cards.json` は編集しない。** `roster.py` の `ROSTER` 表を編集して再生成する。

1. `roster.py` の `ROSTER` に行を足す。1行の形はこう。

   ```
   ("人物", "字号", コスト, 兵種, 役割, S(技名, 対象, [効果...], gauge=消費%),
    ["特性1つ"], {"gauge_start": 初期ゲージ%})     ← 最後の辞書は任意
   ```

   **能力値は書かない。** コスト・兵種・役割・必殺技・特性・勢力から自動で決まる。
   必殺技は全員が固有で、価格は `skill_price` が式で出す（表引きではない）。
   効果を書く補助関数は `D` / `DOT` / `HEAL` / `MOD` / `STUN` / `GAUGE`。
   **持続は100〜150ティックに収める。** 1回目の発動が50秒付近で戦闘が62秒なので、
   それより長くしても捨てるだけになる。
2. `python3 roster.py --write` で `cards.json` を再生成する。
3. `python3 budget.py` を通し、全カードが目標値の許容内に収まることを確認する。
   **ここを飛ばすと、以降のバランス調整がすべて無駄になる。** v0.3 の手置きデータは
   総合値/コストが 歩兵556 / 騎兵701 / 弓兵304 と割れており、兵種補正や射程を
   いくら調整しても弓兵の勝率0%が動かなかった。
4. `python3 balance.py cost` でコストの加算性を確認する。
5. `python3 balance.py troops` で三すくみの向きを確認する。**役割を混ぜた編成の行を見る。**
   役割を揃えた編成は後衛も前衛と同じ硬さになり、騎兵の迂回の価値が中立になるため、
   問題を隠してしまう。
6. `python3 balance.py check` で戦闘時間と必殺技の発動回数を確認する。
7. **固有特性を足した場合は** `balance.py traits` を回し、出力された次の補正値を
   `roster.py` の `TRAIT_ADJUST` へ貼って 2 からやり直す。幅が20pt以下になるまで
   繰り返す（下の「反復のしかた」を見よ）。**必殺技は反復しない。** 80枚それぞれが
   固有なので1反復で80回の測定になり回らない。式で価格を出し、
   `balance.py skillprice` で式そのものの当たり具合を見る。
8. `python3 balance.py meta` で §4.6 の採用率を、`balance.py exploit` で攻略が
   収束していないかを測る。**この2つが実カードでの最終確認になる。**
   合成カードで帯内に入っていても、実カードで歪みが出ることが繰り返し起きている。

## コストと強さの関係

`roster.py` の先頭にある式がすべての能力値を決める。

```
強さ(コスト) = 枠の基礎価値 + コスト比例分
```

`SLOT_VALUE`（枠の基礎価値の割合、現在 0.55）が要点である。0 にすると、コストの低い
武将は相手の火力に耐えられず貢献前に消えるため、同じ合計コストでも配分によって
勝率が0%から65%まで動く。0.55 にすると乖離が大きく縮む。

もう一つのレバーが `engine.WEAR_FLOOR`（消耗係数の下限、現在0.5）である。下限が高いほど
削られても火力を保てるため集中編成が有利になり、低いほど分散編成が有利になる。
この2つを合わせて、配分による勝率の最大乖離は 50pt → 6pt まで縮んでいる。

アイテムにコストを持たせる場合も同じ式に乗せる。アイテムのコストは「コスト比例分」に
だけ加算し、枠の基礎価値は武将1体につき1回しか計上しない。

## 必殺技と固有特性の価格付け

能力値だけを釣り合わせても、その上に乗る必殺技と固有特性が無料だと意味がない。価格付け前は
必殺技の強さに幅67pt、固有特性に幅31ptがあり、勝敗が「どの効果を引いたか」で決まっていた。

```
目標総合値 = value(コスト) ÷ BEHAVIOR_PREMIUM[兵種] ÷ ability_premium(必殺技, 特性)

  ability_premium = 1 + (SKILL_ADJUST[必殺技] + Σ TRAIT_ADJUST[特性]) ÷ 100
```

`SKILL_ADJUST` / `TRAIT_ADJUST` は**「その効果は総合値の何%ぶんか」を直接持つ。勝率では
持たない。** 効果の価値は勝率でしか測れないが予算は総合値で表されており、両者の関係は
非線形（+1%→57%、+3%→68%、+8%→98% と飽和する）なので、換算率で一発割りにはできない。

### どちらの測り方で価格を決めるか

**必殺技は `balance.py support`（1枚だけ混ぜる方式）で決める。**
`balance.py skills`（全員同技の総当たり）では測れない。全員が同じ技を持つと
全体効果の能力補正が上限（±50%）で頭打ちになり、6枚目が何も足さないため
弱く見える。総当たりで curse 46% / rally 53% だったものが、1枚混ぜでは
98% / 97% だった。実際の編成は6枚とも別の技なので、1枚混ぜのほうが実態に近い。

固有特性は `balance.py traits`（特性なしとの対戦）でよい。特性は発動者自身に
かかるものが多く、頭打ちが起きにくい。

### 反復のしかた

測る → 貼る → 測る、を残差が消えるまで繰り返す。

```
新しい補正 = 現在の補正 + (実測勝率 − 50) ÷ ADJUST_STEP
```

`balance.py skills` / `balance.py traits` が次に貼る値をそのまま出力するので、
`roster.py` の表へ貼って `roster.py --write` し、また測る。**幅が20pt以下になったら止める。**
それ以下は測定誤差（skills ±3.5pt / traits ±5.8pt、いずれも2σ）と区別できない。

`ADJUST_STEP`（現在20）は勾配の見込みで、大きいほど慎重に寄る。`balance.py sensitivity` は
6.5pt/% を返すが、**この値を入れると振動する。** sensitivity は両軍の能力を一様に倍する
測り方で、効果を能力へ交換する場面より勾配が緩い。補正を1種類だけ振って測ると釣り合いの
近くでは 10〜30pt/% あった。勾配を過小に見積もると行き過ぎて往復するだけなので、
大きめに倒してある。収束は遅くなるが、遅いのは待てばよく、振動は待っても直らない。

実績: 必殺技 67pt → 7pt、固有特性 31pt → 4pt（3反復）。

### 刻みの下限

**価格付けの分解能は約0.3%で、これより細かい差は表現できない。** 攻撃力は整数で持つため
1点の刻みが総合値の約1.8%（コスト5で atk 56）にあたる。そこで攻撃力の端数は
`roster.solve_hp` が兵力側へ吸収させる。総合値は兵力について線形なので、丸めた攻撃力に
対して兵力を解けばよい。

兵力も50刻みで丸めていたときは刻みが約3%になり、**補正 +0.18〜+2.52% の7種が同一の
hp 3700 / atk 56 に潰れて価格付けがまるごと効いていなかった。** 反復が発散したのは
これが原因で、換算率の問題ではなかった。`balance.py sensitivity` の `scaled_team` も
同じ丸めを持っており、+1% の要求が量子化で0%になって換算率そのものを測り損ねていた。
**検証用のカードを作るときは丸めを持ち込まないこと。**

### 測れていないもの

- `vanguard` は総大将かつ前衛のときだけ働く条件付きで、他と同じ土俵で測れない。暫定値。
- 特性の実測は6人全員が同じ特性を持つ編成で行うため、効果が重なる場面の値になる。
  1〜2枚だけ積む実際の編成より過小評価になりうる（実測の平均は50%をやや下回っている）。

## 測定が嘘をつく型

このリポジトリで繰り返し起きている失敗である。**新しい指標を作ったら、
まず「完全に均衡していたら何が出るか」を計算してから測ること。**

- **偶然による期待値**（母数が足りていれば何枚出るか）
- **対角の値**（同一条件どうしを戦わせれば50%が出るはず）
- **母数から来る2σ**（`100/sqrt(n)` pt。これ以下の差は読んではいけない）

そのうえで、道具そのものの見え方に2つの罠がある。どちらも §4.6 の
「戦闘モデルが小さな差を増幅する」問題の別の顔である。

**実編成のパネルは飽和する。** 実ロスターからサンプルした敵編成を並べて
平均勝率を採ると、強さが揃っていないので10組中8組が 0% か 100% に張り付き、
**数%の能力差がまったく見えない**。「群雄の不利は0.7ptしかない」という数字を
これで出したが、統制した合成パネルで測り直すと −6.7pt だった。
価格付けには**統制した合成カード**を使う。実編成は最終確認にだけ使う。

**統制したパネルは量子化で過敏になる。** 攻撃力は整数で持つため、価格を
少し動かすと hp と atk の配分が入れ替わる。総合値は上がっているのに、
被ダメージ増加のかかる相手には耐久のほうが効くので成績が落ちる。
勝率は**のこぎり波**になり、勾配1歩の反復は谷を踏み抜いて逆行する。

```
FACTION_ADJUST   -1.05  -1.35  -1.70  -2.00
群の勝率          50.7   51.7   45.7   46.0     ← -1.70 で atk 56→57
```

**反復ではなく範囲を掃いて、谷から離れた平坦部を選ぶ。**

この2つは避けられない。**戦闘モデルの増幅は v0.5 末に案A〜Fを実測したうえで
「消さない」と決めた**（仕様書 §4.6・案D）。増幅を緩める案はどれも兵種三すくみを
一緒に潰し、兵種補正を振り直しても3方向が同時に帯へ入る値は無かった。
三すくみの +4% が 67% になるのも同じ60秒の複利によるもので、片方だけは消せない。
したがって**増幅がある前提で測る作法のほうを守る**。

## 実装上の約束

仕様書 §8.4 の再現性要件に対応する。

- **すべて整数演算**。浮動小数点は一切使わない。位置と射程は1単位=10、必殺技ゲージは最大100を10000で保持する。
- **乱数は xorshift64\* をシードから回す**。消費順序は §8.1 の処理順序に厳密に従う。
- **同じ (編成, 配置, 戦場条件, シード) なら必ず同じ結果**になる。`balance.py check` が毎回検証する。
- 先攻側もシードから決定論的に決まる。

## 仕様書との差分

実装にあたって仕様書に無い判断が必要だった箇所、および実測の結果として仕様書側を
変更すべきと判断した箇所は、仕様書の §0.3〜§0.5 に一覧としてまとめる。主なものは以下。

- 弓兵の標的選択を「射程内で残兵力率が最も低い敵」とした。総大将を名指しで狙わせると、
  部隊戦が「どちらが先に総大将を落とすか」の競争に収束し、編成と配置が結果に
  反映されなくなるため。
- 必殺技ゲージの時間経過分を 1.0/秒 から 2.0/秒 へ引き上げた。v0.2.1 の
  「60秒で1回目・平均1.2回・上限90秒」は同時に満たせないため（2回目に更に60秒必要）。
- 決着促進を追加した。導入前は部隊戦の31%が時間切れ決着だった。
- コストと強さの関係を「枠の基礎価値 + コスト比例分」に変えた。コスト比例のみだと、
  同じ合計コストでも配分によって勝率が0%から65%まで動いた。
- 補正の固定値を廃した。必殺技のゲージ付与と撃破時のゲージ加算は「自然増加の何秒ぶん」で
  定義する。固定量で与えると、ゲージ上昇率の低い武将ほど相対的に得をする。
- 撤退した武将のゲージを生存味方へ引き継ぐようにした（部隊全体資産）。部隊が1体減ると
  必殺技と固有特性がまるごと失われるため、能力値では釣り合わせられない不利が生じる。
- 消耗係数の下限を0.6から0.5へ下げた。コストの加算性を直接動かすレバーだった。
- 誘発型の固有特性を実装した。連鎖は禁じている（決定論と実況の可読性のため）。
- 前衛を後衛の盾にし、迂回・孤立・接敵抑制・後退射撃・陣形を追加した。配置に戦術の軸を
  作るため。**迂回は時間で表す。** 「突破できる／できない」の二値にすると、抑えの値が
  5か6かだけで無敵の型が入れ替わり、中間が存在しなかった。時間なら前衛の人数に比例して
  連続的に高くつく。あわせて騎兵は「後衛に前衛より柔らかい札がいるときだけ」回り込む。
  無条件だと同じ硬さの後衛のために攻撃時間を捨てる。陣形メタは循環するようになり
  （天敵のない型が消えた）、兵種三すくみも3方向とも目標帯へ入った。
  型ごとの強さの幅は60pt残っている（仕様書 §13）。
- 必殺技と固有特性の価値をコスト予算へ織り込んだ。能力値だけを釣り合わせても、
  その上に乗る効果が無料だと勝敗が効果の引きで決まってしまう。

## カードデータの見方

`cards.json` の1枚はこの形式。

```json
{
  "id": "choryo_7", "person": "張遼", "name": "張遼〔逍遥津〕", "tier": "high",
  "cost": 7, "troop": "cav", "role": "bruiser",
  "hp": 3750, "atk": 62, "dfn": 46, "speed": 12,
  "gauge_rate": 100, "acc": 90, "crit": 14, "power": 118,
  "skill": {"name": "突撃", "target": "front_enemy",
            "effects": [{"type": "damage", "power": 190}]}
}
```

`hp` / `atk` / `dfn` / `speed` / `gauge_rate` / `acc` / `crit` は `roster.py` が
コスト・兵種・役割から計算した結果である。手で書き換えても次の生成で消える。

- `person` は人物ID（§4.3 の重複判定の単位）、`id` は武将カードID。
- `troop` は `inf`（歩兵）/ `cav`（騎兵）/ `arc`（弓兵）。攻撃間隔・射程・回避の
  兵種標準値は `troop_defaults` にまとめてある。
- `gauge_rate` は100が標準（1.0倍）。
- `power` は実力比（コスト5を100とする）。能力補正の%・行動阻害のティック数・
  ゲージ付与の量に掛かる。**コストではなく実際の総合値から出す**ので、価格付けで
  能力値を削られたカードは効果量も下がる。これがないと値上げが効かない。
- `speed` は1秒あたりの前進量（レーン奥行きは100単位）。

必殺技の `target` と `effects[].type` に指定できる値は `engine.py` の
`skill_targets()` と `cast()` を参照。

| target | 対象 |
| --- | --- |
| `front_enemy` | 正面の敵（自レーンの前衛優先） |
| `lane_enemies` | 自レーンの敵全体 |
| `enemy_back_lane` | 自レーンの敵後衛 |
| `enemy_lowest` | 敵全体のうち残兵力が最小 |
| `all_enemies` / `all_allies` | 敵全体 / 味方全体 |
| `lane_allies` / `lowest_ally` / `self` | 自レーンの味方 / 最も兵力の低い味方 / 自分 |

| type | 効果 |
| --- | --- |
| `damage` | `power` は攻撃力に対する% |
| `mod` | `stat`（atk/dfn/acc/speed）を `value`% だけ増減、`duration` ティック |
| `stun` | `duration` ティックのあいだ行動阻害 |
| `dot` | `interval` ティックごとに継続ダメージ |
| `gauge` | 必殺技ゲージを増減。`seconds` で「自然増加の何秒ぶん」を指定する |
| `heal` | 兵力を回復。`power` は**発動者の攻撃力に対する%**（固定量にはしない） |

必殺技は `gauge` で消費ゲージ（満タンを100とした%）を指定できる。省略すると100。
カード側は `gauge_rate`（獲得速度）と `gauge_start`（初期ゲージ%）を持てる。
**この3つは個別に価格を付けない。** どれも発動回数にしか効かず、その価値は
技の中身と掛け算になるため、まとめて発動回数へ畳んでから技の価格に織り込む
（`roster.casts_for` → `roster.skill_price`）。

実測の発動回数（1体・1戦あたり）:

```
消費   50%  3.45回   100%  1.63回   150%  0.93回   200%  0.65回   300%  0.50回
速度  130%  2.14回    70%  1.17回
初期   25%  1.86回    50%  2.13回
```

**ゲージ付与の上限は満タンではなく消費量に合わせること**（`gauge_ceiling`）。
満タン固定のままにすると、消費100超の技だけが撃破ゲージとゲージ引き継ぎを
受け取れず、200%で0.07回しか撃てない。最初にこれで「使える消費は50〜125%
しかない」と誤った結論を出しかけた。

## 固有特性

`traits` は2種類を混在させられる。

- **文字列**（`"vanguard"`）は常在型。エンジン側に処理を持つ組み込み特性。
- **オブジェクト**は誘発型。`roster.py` の `TRIGGERS` に定義し、ロスター表ではキーで参照する。

```json
{"name": "遺志", "trigger": "ally_retreat", "target": "self", "limit": 3,
 "effects": [{"type": "mod", "stat": "atk", "value": 15, "duration": 200}]}
```

| trigger | 誘発条件 |
| --- | --- |
| `ally_retreat` | 味方が撤退したとき |
| `enemy_retreat` | 敵を撤退させたとき |
| `self_low_hp` | 自身の兵力が `threshold`% 以下になったとき |
| `ally_skill` | 味方の必殺技が発動したとき |

`effects` と `target` は必殺技と同じ形式。`limit` は1戦闘あたりの発動回数の上限（既定1）。

**誘発の連鎖は起きない。** 誘発型の効果が別の誘発型を誘発することはエンジン側で禁じている。
連鎖を許すと発動順序と回数が編成によって変わり、決定論が実質的に壊れるため。
