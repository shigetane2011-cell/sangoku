# 戦闘シミュレータ

仕様書 v0.5 の §5〜§8 を実装し、§4.6 のバランス指標が実際に測定できるかを確かめるための
検証環境。ゲーム本体ではなく、**数値設計の妥当性を測るための道具**である。

外部ライブラリは不要（Python 3.10 以上の標準ライブラリのみ）。

## ファイル

| パス | 内容 |
| --- | --- |
| `roster.py` | **武将ロスターの定義と `cards.json` の生成器**。人物・コスト・兵種・役割・必殺技だけを持ち、能力値はコストから導出する。 |
| `cards.json` | `roster.py` が生成する武将データ60人ぶん。**手で編集しない**。 |
| `engine.py` | 部隊戦の戦闘エンジン。§8.1 の12ステップをティックごとに処理する。 |
| `balance.py` | バランス検証ハーネス。§4.6 の指標を実測する。 |
| `budget.py` | 各カードがコスト式どおりの能力値かを検算する。ロスターを変更したら必ず通す。 |

## 実行

```
cd sim
python3 engine.py            # 1戦を実況付きで再生（動作確認）
python3 balance.py check     # 決定論・戦闘時間・決着理由・必殺技回数
python3 balance.py troops    # 兵種三すくみ（合計コストを揃えて比較）
python3 balance.py commander # 総大将の前衛配置と後衛配置の勝率差
python3 balance.py swap      # 差し替え勝率（§4.6 目標 47-53%）
python3 balance.py meta      # 採用率
python3 balance.py cost      # コストの加算性
python3 balance.py skills    # 必殺技のひな型ごとの強さ
python3 balance.py traits    # 誘発型の固有特性ごとの強さ
python3 balance.py all       # すべて
python3 budget.py            # 能力値がコスト式どおりかの検算
python3 roster.py --write    # ロスターから cards.json を再生成
```

`swap` と `meta` は数万回の対戦を行うため、数分かかる。

## 武将を追加・変更したときの手順

**`cards.json` は編集しない。** `roster.py` の `ROSTER` 表を編集して再生成する。

1. `roster.py` の `ROSTER` に行を足す（人物・字号・コスト・兵種・役割・必殺技・特性）。
   能力値は書かない。コストと兵種と役割から自動で決まる。
2. `python3 roster.py --write` で `cards.json` を再生成する。
3. `python3 budget.py` を通し、全カードが目標値の許容内に収まることを確認する。
   **ここを飛ばすと、以降のバランス調整がすべて無駄になる。** v0.3 の手置きデータは
   総合値/コストが 歩兵556 / 騎兵701 / 弓兵304 と割れており、兵種補正や射程を
   いくら調整しても弓兵の勝率0%が動かなかった。
4. `python3 balance.py cost` でコストの加算性を確認する。
5. `python3 balance.py troops` で三すくみの向きを確認する。
6. `python3 balance.py check` で戦闘時間と必殺技の発動回数を確認する。
7. `python3 balance.py meta` で §4.6 の採用率を測る。

## コストと強さの関係

`roster.py` の先頭にある式がすべての能力値を決める。

```
強さ(コスト) = 枠の基礎価値 + コスト比例分
```

`SLOT_VALUE`（枠の基礎価値の割合、現在 0.55）が要点である。0 にすると、コストの低い
武将は相手の火力に耐えられず貢献前に消えるため、同じ合計コストでも配分によって
勝率が0%から65%まで動く。0.55 にすると乖離が大きく縮む。

もう一つのレバーが `engine.WEAR_FLOOR`（消耗係数の下限、現在0.5）である。下限が高いほど
削られても火力を保てるため集中編成が有利になり、低いほど分散編成が有利になる。
この2つを合わせて、配分による勝率の最大乖離は 50pt → 6pt まで縮んでいる。

アイテムにコストを持たせる場合も同じ式に乗せる。アイテムのコストは「コスト比例分」に
だけ加算し、枠の基礎価値は武将1体につき1回しか計上しない。

## 実装上の約束

仕様書 §8.4 の再現性要件に対応する。

- **すべて整数演算**。浮動小数点は一切使わない。位置と射程は1単位=10、必殺技ゲージは最大100を10000で保持する。
- **乱数は xorshift64\* をシードから回す**。消費順序は §8.1 の処理順序に厳密に従う。
- **同じ (編成, 配置, 戦場条件, シード) なら必ず同じ結果**になる。`balance.py check` が毎回検証する。
- 先攻側もシードから決定論的に決まる。

## 仕様書との差分

実装にあたって仕様書に無い判断が必要だった箇所、および実測の結果として仕様書側を
変更すべきと判断した箇所は、仕様書の §0.3〜§0.5 に一覧としてまとめる。主なものは以下。

- 弓兵の標的選択を「射程内で残兵力率が最も低い敵」とした。総大将を名指しで狙わせると、
  部隊戦が「どちらが先に総大将を落とすか」の競争に収束し、編成と配置が結果に
  反映されなくなるため。
- 必殺技ゲージの時間経過分を 1.0/秒 から 2.0/秒 へ引き上げた。v0.2.1 の
  「60秒で1回目・平均1.2回・上限90秒」は同時に満たせないため（2回目に更に60秒必要）。
- 決着促進を追加した。導入前は部隊戦の31%が時間切れ決着だった。
- コストと強さの関係を「枠の基礎価値 + コスト比例分」に変えた。コスト比例のみだと、
  同じ合計コストでも配分によって勝率が0%から65%まで動いた。
- 補正の固定値を廃した。必殺技のゲージ付与と撃破時のゲージ加算は「自然増加の何秒ぶん」で
  定義する。固定量で与えると、ゲージ上昇率の低い武将ほど相対的に得をする。
- 撤退した武将のゲージを生存味方へ引き継ぐようにした（部隊全体資産）。部隊が1体減ると
  必殺技と固有特性がまるごと失われるため、能力値では釣り合わせられない不利が生じる。
- 消耗係数の下限を0.6から0.5へ下げた。コストの加算性を直接動かすレバーだった。
- 誘発型の固有特性を実装した。連鎖は禁じている（決定論と実況の可読性のため）。

## カードデータの見方

`cards.json` の1枚はこの形式。

```json
{
  "id": "choryo_7", "person": "張遼", "name": "張遼〔逍遥津〕", "tier": "high",
  "cost": 7, "troop": "cav", "role": "bruiser",
  "hp": 3750, "atk": 62, "dfn": 46, "speed": 12,
  "gauge_rate": 100, "acc": 90, "crit": 14,
  "skill": {"name": "突撃", "target": "front_enemy",
            "effects": [{"type": "damage", "power": 190}]}
}
```

`hp` / `atk` / `dfn` / `speed` / `gauge_rate` / `acc` / `crit` は `roster.py` が
コスト・兵種・役割から計算した結果である。手で書き換えても次の生成で消える。

- `person` は人物ID（§4.3 の重複判定の単位）、`id` は武将カードID。
- `troop` は `inf`（歩兵）/ `cav`（騎兵）/ `arc`（弓兵）。攻撃間隔・射程・回避の
  兵種標準値は `troop_defaults` にまとめてある。
- `gauge_rate` は100が標準（1.0倍）。
- `speed` は1秒あたりの前進量（レーン奥行きは100単位）。

必殺技の `target` と `effects[].type` に指定できる値は `engine.py` の
`skill_targets()` と `cast()` を参照。

| target | 対象 |
| --- | --- |
| `front_enemy` | 正面の敵（自レーンの前衛優先） |
| `lane_enemies` | 自レーンの敵全体 |
| `enemy_back_lane` | 自レーンの敵後衛 |
| `enemy_lowest` | 敵全体のうち残兵力が最小 |
| `all_enemies` / `all_allies` | 敵全体 / 味方全体 |
| `lane_allies` / `lowest_ally` / `self` | 自レーンの味方 / 最も兵力の低い味方 / 自分 |

| type | 効果 |
| --- | --- |
| `damage` | `power` は攻撃力に対する% |
| `mod` | `stat`（atk/dfn/acc/speed）を `value`% だけ増減、`duration` ティック |
| `stun` | `duration` ティックのあいだ行動阻害 |
| `dot` | `interval` ティックごとに継続ダメージ |
| `gauge` | 必殺技ゲージを増減。`seconds` で「自然増加の何秒ぶん」を指定する |

## 固有特性

`traits` は2種類を混在させられる。

- **文字列**（`"vanguard"`）は常在型。エンジン側に処理を持つ組み込み特性。
- **オブジェクト**は誘発型。`roster.py` の `TRIGGERS` に定義し、ロスター表ではキーで参照する。

```json
{"name": "遺志", "trigger": "ally_retreat", "target": "self", "limit": 3,
 "effects": [{"type": "mod", "stat": "atk", "value": 15, "duration": 200}]}
```

| trigger | 誘発条件 |
| --- | --- |
| `ally_retreat` | 味方が撤退したとき |
| `enemy_retreat` | 敵を撤退させたとき |
| `self_low_hp` | 自身の兵力が `threshold`% 以下になったとき |
| `ally_skill` | 味方の必殺技が発動したとき |

`effects` と `target` は必殺技と同じ形式。`limit` は1戦闘あたりの発動回数の上限（既定1）。

**誘発の連鎖は起きない。** 誘発型の効果が別の誘発型を誘発することはエンジン側で禁じている。
連鎖を許すと発動順序と回数が編成によって変わり、決定論が実質的に壊れるため。
