# 戦闘シミュレータ

仕様書 `docs/spec/basic-game-spec-v0.5.md` の §5〜§8 を実装し、§4.6 のバランス指標が
実際に測定できるかを確かめるための検証環境。ゲーム本体ではなく、**数値設計の妥当性を
測るための道具**である。

外部ライブラリは不要（Python 3.10 以上の標準ライブラリのみ）。

## ファイル

| パス | 内容 |
| --- | --- |
| `field.py` | **盤面と戦闘エンジン。** レーンを持たない連続座標（x, y）。測定コマンドもここ |
| `design.py` | **武将の設計式。** コスト → 能力値。効果予算（必殺技・固有特性の値段）もここ |
| `rosterdata.py` | `data/*.csv` の読み込み・検算・書き出し。`field.Card` への橋渡し |
| `data/generals.csv` | 武将80枚。**盤面が実際に使う値が入っている**（下記） |
| `data/skills.csv` | 必殺技80種 |
| `data/traits.csv` | 固有特性19種 |
| `old/` | **レーン・総大将時代の旧実装。保管のみ。動かさないこと**（`old/README.md`） |

## 実行

```
python3 -m sim.rosterdata            # CSV の検算（盤面・設計式・CSV の3方向）
python3 -m sim.design                # 設計式の検算（4項）

python3 -m sim.field zero            # 零点。同じ編成どうしで 0.00 か
python3 -m sim.field selftest        # 計器の自己診断（陽性対照つき）
python3 -m sim.field cost            # コストの加算性
python3 -m sim.field triangle        # 兵種の三すくみ
python3 -m sim.field formation       # 陣形
python3 -m sim.field price           # 行動面の係数の較正（ACT_COEF）
python3 -m sim.field calibrate       # 兵種相性の較正（TYPE_EDGE_COST）
python3 -m sim.field heal            # 回復とダメージの交換レート
python3 -m sim.field dot             # 継続ダメージ 対 打ち切り
python3 -m sim.field traits          # 固有特性の値段
python3 -m sim.field narrate         # 実況の出力例
python3 -m sim.field spread          # 戦列が横へ広がっていないか
```

`price` と `calibrate` は総当たりを反復するため数分かかる。`--skills` で必殺技を
オンにして測る（**既定の較正値は技オンで取ってある**。§7.9）。

## 測り方の約束（仕様書 §13）

ここを外すと、以降の調整がすべて無駄になる。実際に17件の「測定が嘘をついた」事例が
記録してある。

- 新しい指標を作ったら、まず「完全に均衡していたら何が出るか」を計算する
- **零点（同じ編成どうし）を毎回測る。50%だと仮定しない。条件を変えたら測り直す**
- 時間刻み・威力など自由なパラメータを振り、符号が変わらないものだけを結論に使う
- **全部ゼロが並んだら、まず計器を疑う。同じ値が並ぶのも同じ合図**
- 移動の規則に分岐を入れると時間刻みに依存する。距離だけで決まる連続な形にする
- 帯に入る値を見つけたら、その隣を測って崖の上でないか確かめる
- 説明が当たったと思ったら、その説明が外れるはずの条件を作って測る
- **勝率は使わない。** 決定論の盤面では総コスト0.1点で100%に飽和する。コスト点で測る

## 武将を追加・変更したときの手順

**CSV が一次、`design.py` は生成器。**

1. `data/generals.csv` に行を足す（名前・勢力・コスト・兵種・役割・必殺技・固有特性・
   ゲージ3項目）。能力値の列は空でよい。
2. `python3 -c "from sim import rosterdata as R; R.regenerate()"` で能力値を引き直す。
3. `python3 -m sim.rosterdata` を通す。**ここを飛ばさない。**
4. 必殺技や固有特性を足したなら `python3 -m sim.field traits` を回し、
   `design.TRAIT_PRICE` を書き直す。
5. `python3 -m sim.field zero` と `cost` で零点と加算性を確認する。

1枚だけ手で調整したいときは CSV を直接編集してよい（`regenerate()` を走らせると
上書きされる）。CSV と設計式の食い違いは `rosterdata.check()` が捕まえる。

## コストと強さの関係

```
総合値(コスト) = 枠の基礎価値 + コスト比例分        （design.total_power）
能力値コスト   = 表示コスト − 効果予算              （§7.8）
```

1部隊は6枠固定なので、この形なら**合計コストが同じ編成は配分によらず総価値が等しい**。
コストは全額が **兵力** に乗る（`SPLIT_EXP = 1.0`）。ここを 1.0 未満にすると軍全体の
兵力が劣加法になり、加算性が壊れる。

武力・知力は**その武将個人の力**で、コストに比例する。攻撃力は導出値。

```
攻撃力 = ( 武力×(1-w) + 知力×w ) ÷ (兵力 / 基準兵力)      w = INT_WEIGHT[兵種]
```

## 効果予算

必殺技と固有特性は無料ではない。値段ぶん能力値を下げる。

| | 出どころ |
| --- | --- |
| 必殺技 | `design.effect_value()`。実カード36種で当てた単価（誤差 平均0.062コスト点） |
| 固有特性 | `design.TRAIT_PRICE`。**式ではなく測った表**（`field.py traits` で更新） |

固有特性を式にしないのは、値段が「いつ発動したか」で決まるためである。背水
（攻撃力+25%・90秒）は必殺技と同じ式なら 2.96 だが実測 0.096 で30倍ずれる。

## 現行の較正値（すべて技オンで測定）

| | 歩兵 | 騎兵 | 弓兵 |
| --- | --- | --- | --- |
| 行動面の係数 `ACT_COEF` | 1.0000 | 1.0659 | 0.8839 |
| 防御力 `DEF_BY_TYPE` | 56.6 | 42.3 | 34.0 |
| 知力の重み `INT_WEIGHT` | 0.10 | 0.10 | 0.35 |

| 兵種相性 `TYPE_EDGE_COST` | 歩→騎 | 騎→弓 | 弓→歩 |
| --- | --- | --- | --- |
| 値 | 0.4916 | 2.6956 | 2.5763 |
| 実測（コスト点） | +1.001 | +0.958 | +1.002 |

推移幅 0.029、巡回成分 +0.987。加算性は 7/3 で -0.015、9/1 で -0.044。

## 仕様書との差分

実装にあたっての判断と実測結果は、仕様書の §7.6〜§7.11 および §13 に記録してある。
主なものは以下。

- レーンを廃し、連続座標の盤面にした。側背・遮蔽・迂回は特別規則ではなく実座標から出す
- 総大将を廃し、「軍全体の残存20%割れで潰走」にした。加算性が壊れる原因だった
- 勝率を捨て、コスト点を物差しにした。決定論の盤面で勝率は飽和して測れない
- 矢数を「敵の消耗割合」と連動させた。決着の速さと兵種バランスの結合を切るため
- 必殺技のダメージを武力・知力ベースにした。兵力に比例しないので増幅に乗らない
- 継続ダメージを毎秒の量で持つ。総量を1発で入れると打ち切り技と区別が付かない
- 固有特性を必殺技と同じ器へ載せた。誘発の閾値は潰走（15%）とは別に30%で持つ
